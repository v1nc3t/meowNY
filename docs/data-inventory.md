# Data inventory

What data this app holds, where it lives, which optional network calls exist, and who else could see it. Update this page in every phase. This is a technical note, not a privacy policy.

meowNY is local-first: no server, no accounts, no telemetry. All data stays on the user's own devices. Nobody operates a service, so there is no operator or controller holding anyone's data.

Status: end of phase 7. Built: the encrypted database and its migrations, key handling, app lock and "delete all my data", categories, transactions, budgets, recurring items, statistics, backup and restore (also on a schedule) and export to JSON, CSV, Excel and PDF. In phase 7: the storage for CLI access tokens, the local command API server (off by default; read routes show what the screens show except the lock settings, the backup passphrase and the tokens; write routes for categories, transactions, budgets, recurring items and the number format, time zone and language need a write token; exports and backups are written only after the person allows each one in a dialog in the app; nothing reaches the currency, the lock settings, the tokens, restoring a backup or "delete all my data"), the Settings switch and token screen, the command line program `meowny` (desktop only) and its documentation site. Not built yet: documents (9) and debts and expense splitting (10); their rows below are plans. The old server-based design (Postgres, accounts, sessions, consents) is retired and is only in git history.

Last checked against the code (`src-tauri/src`, `ui/src`) and the files the app leaves on disk. A search of the whole data folder (the database and its journal files, `vault.json` and the webview's cache and storage, over 4,500 files) for text that exists only in the demo data found it in none of the plain places.

## What leaves the app without a network call

| What | Detail |
|---|---|
| Desktop notifications | Once a day while the app is unlocked, the names of recurring items that are due or overdue (a few names, then "…"). The operating system shows them and may keep a notification history. On by default; Settings, notifications, turns it off |
| The clipboard | The recovery key, or a new CLI token, only when "copy" is pressed. It stays there until something else is copied |
| Files | Backups, exports and the recovery key go where the user saves them. The app does not track the ones saved by hand and cannot remove them |
| Links | An https link opens in the system browser, only when it is clicked |
| The camera (phone only) | Opened only while the person is scanning a code from the desktop, after the system's own permission question. The picture is read for a QR code inside the camera plugin; the app keeps no picture, and nothing is recorded or sent |

## Network calls

None today. The page content policy allows only the app itself and its own command channel, and `npm run check:outbound` in CI lists every place the code could make an outbound call and fails on a new one. Nothing leaves the device unless the user turns a feature on:

| Call | When | What is sent | To whom |
|---|---|---|---|
| Update check | Phase 11, a visible setting | App version and platform | The project's release host |
| Phone sync | Phase 8, each time you start it on the desktop. The desktop listens for about two minutes (five for a pairing) on its home-network address and takes one connection that proves two secrets; everything else is closed without an answer | Changes, sealed with keys that come from the pairing secret and a one-time QR code. The check code of a pairing, the name of each device, and the address and port in the QR code | The paired phone only, directly on the home network. No server, relay or other party is involved. A QR code that names an address outside the home network is refused |

## What the app accepts from the same computer

| What | Detail |
|---|---|
| Command API (phase 7) | Off by default; Settings, command line access, turns it on. When on, the app listens on `127.0.0.1` only, on a port the system picks, so nothing on the network can reach it. Every request needs a token made in the app. A web page in the user's browser cannot use it: a request with an `Origin` header or a `Host` that is not the loopback address and this port is refused, and the API sends no CORS headers. An export or a backup is written only after the person allows it, each time, in a dialog in the app (see below). A locked app answers "locked" and no data. Calls do not count as activity, so the idle lock still works. The server logs nothing. A script that holds a token can read (or, with a write token, change) the data while the app is unlocked, which is why tokens are read-only by default, expire and can be revoked |

Restoring a backup, changing the currency, the lock settings, tokens, setting up a scheduled backup and "delete all my data" cannot be reached through the command API at all, with or without the person's yes: they are done in the app.

## "Delete all my data"

Removes the database and its journal files, `vault.json` (which holds the two wrapped copies of the key and the lock settings), any backups in the `backups` folder of the data folder (nothing writes there today), and the key in the OS keychain. Without that key, a leftover copy of the database file cannot be opened. The scheduled backup setup and the CLI tokens go with the database. The command API's port file (`api.json`) is removed too, and the API stops listening.

Leaves behind: a token file saved by `meowny login` (it stops working, because the tokens are in the database, but `meowny logout` removes the file); backups and exports saved elsewhere, including the scheduled backups in the folder the user picked; the interface preferences in the webview's storage (language, sidebar state, the date of the last notification; no financial data) and WebKit's own folders; and whatever is on the clipboard or in the operating system's notification history.

## Logs

Logs and crash reports never contain amounts, descriptions, tokens or keys. Errors cross into the UI as fixed codes, database error text is dropped, and the panic hook prints only the source location. The development command `dev_vault` prints counts and the new recovery key of demo data; it is not part of the app.

## Not collected

Analytics, telemetry, advertising identifiers and remote error reports.
